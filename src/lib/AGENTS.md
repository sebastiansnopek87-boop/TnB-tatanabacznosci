- Admin e-mails: notifications.server.ts, configured by single-row email_settings, logged to email_notification_log.
- Control Center aggregates read-only queries (never list helpers with cleanup/identity writes), imports hasAccess inside its server handler, and pages history by exact object separately from actor history; why: preserve access truth, data integrity and complete order history without new registries.
- Newsletter stores consent text/version/time + opt-in method; active only when the opt-in rule is satisfied.
- Community: guests read only public+published posts via anon RLS/column grants (no author_id); writes authenticated-only.
- Library: metadata in library_items (anon, published); content in library_item_content gated by library_can_read(); files via signed URLs, covers via /api/public/library-cover/$id. Premium = paid library_orders row, never the premium role.
- Orders/payments: orders.server.ts is the single order core for bank transfer and operators (payments/providers.server.ts adapters: P24, Tpay, PayU; config in payment_providers, secrets only in env). "paid" only via signature-verified webhook (/api/public/payments/$op, dedup in payment_webhook_events, amount/currency check → needs_review) or admin confirming a bank_transfer order. Access = paid_at set, access_revoked_at null, status paid/refund_pending/refunded; linked to user_id or confirmed account e-mail.
- Meetings: public reads with explicit safe columns (online_link hidden); registrations server-only with honeypot, per-email uniqueness, DB capacity trigger.
- Podcast: admin-only RLS; public reads via safe columns; media returned by getEpisodeMedia (signed 3h) only after access check.
- 1:1 consults: slots computed server-side (Europe/Warsaw); DB exclusion constraint blocks double booking; booking + meeting-registration e-mails go through dispatch() (consult.server.ts, meetings-notify.server.ts), meeting links only via token status pages; reminders cron not yet scheduled.
- Articles (/artykuly, articles.functions.ts): own tables articles/article_categories/article_settings, separate from community posts and library; content blocks reuse the CMS PageSection model + shared SectionsEditor/PageSections; images in private bucket article-images via /api/public/article-image only when published+released+referenced. Why: editorial texts stay separate without a second editor.
- CMS: reuse site_pages (JSONB sections) for new content pages; images via /api/public/page-image only when published+referenced.
- Media panel (/admin/multimedia, media.functions.ts): lists files of existing private buckets via service-role admin_media_objects(); usage computed live from module tables; new uploads go to private bucket 'media'; delete only when no usage. Why: no duplicate storage or file-copy.

- Builder templates: builder_templates holds copies of PageSection config (admin-only RLS, server fns in src/lib/templates.functions.ts); images copied into templates/<id>/ and again into the page on insert. Why: inserted copies are independent, deleting a template never breaks pages.
- Article newsletter: optional per published article in article_newsletters (writes only via server fns, admin read-only RLS); recipients = newsletter_subscribers status=active, each message via dispatch() event newsletter_article; send = superadmin + explicit confirm; "sent" only after real delivery. Why: reuse list and mail engine, no auto-send.
- Library catalogue: Biblioteka TNB is the single catalogue for free, members-only and paid materials; filters live in the URL (dostep/format/kategoria/sort/q) and /materialy-premium redirects to ?dostep=premium. Why: one catalogue, no duplicate premium module.
- Biblioteka materials follow the editorial standard in src/config/editorial.ts, shown read-only at /admin/standardy; why: static content needs no table and is versioned with code.
- Library PDFs: new uploads go through src/lib/library/pdf.server.ts (original in originals/, only the watermarked copy becomes file_path; failed -> no file served); free-material delivery modes (direct/form_download/email) + every download/request logged in library_requests (admin-only reads, 12-month retention). Why: no unmarked file ever served, one register.
